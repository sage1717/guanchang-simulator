# [mvu_plot] 通讯界面协议

<通讯界面协议>
线上通讯（短信/微信）用专用界面块呈现，正文只写动作过渡。

标记:
- 年份 2010 及以前 = 短信时代, 用 <sms> 块
- 年份 2011 起 = 微信时代, 用 <wx> 块
- 块格式:
  [联系人|对方名字]
  {收|对方发来的消息}
  {发|主角回复的内容}
  微信时代 {收|对方名字|消息} 只用于群聊/多人场合, 单人聊天不需要名字
  例:
  <sms>
  [联系人|王书记]
  {收|小谢，材料明天早上八点半前送过来}
  {发|好的书记，我提前到}
  </sms>

主角=发消息的人, 用 {发|...}; 对方来的用 {收|...}.
一次线上互动一个块, 多句话全放块里, 块外正文一句带过(如"他把手机放回兜里，快步往办公楼走").

输出位置铁律（最高优先级）:
- 思考/推理过程(thinking/思维链/任何内部草稿)中禁止出现任何尖括号字符 < 和 >——一个都不允许; 规划通讯时只用自然语言(如"主角发短信回复对方"), 标签一律留到正式正文.
- <sms>/<wx> 标记块只出现在最终回复的正文里, 且必须完整: 成对开闭标签 + [联系人|X] + {收|...}/{发|...} 行; 严禁半截标签、孤立的 </sms> 或 <wx> 之类残片.
- 正文中除通讯标记块外不使用任何尖括号标签(如 <narrative_voice> 等一律禁止).
- 标记块不完整时宁可放弃块、用普通文字描述对话, 也不要输出残缺标签.

用户输入的口语格式(用户说这些=主角在发消息, AI 按年份用对应块呈现互动):
- "发信息/发短信/发微信/发消息给X：内容" = 主角主动给 X 发
- "X发信息/短信/微信给我：内容" / "X微信我说：内容" = X 主动发来
- "回X：内容" / "回复X：内容" = 主角回复 X 刚才的消息
AI 的回复里用 <sms>/<wx> 块把这个互动完整呈现(主角发的和对方回的都在块里), 不要只在正文里复述.
</通讯界面协议>
